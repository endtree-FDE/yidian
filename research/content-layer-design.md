# 一点 · 内容层设计（回看时到底带回来什么）

> 这一轮的问题不是「功能够不够」「能不能装上」，而是：**一点带回来的到底是内容，还是只是内容的坐标？**
>
> 结论先说：改之前，一点存的是**坐标** —— 一个链接、一个标题、有时还有你当时正好选中的一段。
> 改之后，它多存**一句页面自己写的描述**；桌面端收下的东西不再只有「域名 · 时间 收藏」。

---

## 1. 改之前：内容这一层的真实状态

记录里到底有什么（`packages/yidian-core/domain.mjs` 的 `createRecord`）：

| 有 | 没有 |
|---|---|
| 标题 `title` | ❌ 正文 / 全文 |
| 选段 `excerpt`（≤1000 字） | ❌ 页面快照（DOM、截图） |
| 链接 `url` / `canonicalUrl` | ❌ 摘要 / AI 提炼 |
| 域名 `sourceDomain` | ❌ 缩略图 / og:image |
| 进度 `stage` 1–4 + 到期时间 | ❌ 读到第几屏（阅读位置） |
| 足迹 `encounters` | ❌ 标签、备注、划线集合 |
| | ❌ 原文副本（链接挂了就没了） |

三处具体的不好用：

**① 回看那一刻，你还是得把原来的事重做一遍。**
卡片给的是「标题 + 域名 + 一句选段 + 一个链接」，点「打开原网页」直接跳浏览器。
间隔重复的收益本来在于「重新拿回内容」，但每次回来拿回的是导航信息，不是内容本身。

**② 主产品的采集通道几乎是空的 —— 这是最尖锐的缺陷。**
桌面端 `captureUrl()` 明确传 `tab: { title: '', url: picked, excerpt: '' }`，
剪贴板那条传 `title: url`。结果是桌面端收的东西：标题走兜底「example.com · 11-14 02:31 收藏」、**摘录恒为空**。
桌面端是主产品，但它收的东西比扩展弱 —— 扩展至少能拿到 `document.title` 和你正好选中的那段。

**③ 没有留存，就经不起时间。**
链接会 404、会改版、会被付费墙挡住。反复收藏不读的东西，三个月后只剩一个域名加一段选段。

### 成熟产品在做什么（可抄的一条）

Readwise Reader / Raindrop / Obsidian Web Clipper 有个共同点：**回看时交付的是「你当时划过的原文片段」，链接只是入口**；
Raindrop 还会顺手存一份正文快照。
一点原本站在这条线的另一边 —— 交付的是坐标。这条差异不是功能多寡，是产品定位。

## 2. 这一轮做了什么：采集端补内容

范围（问卷确认）：**采集端补内容** + **只抓标题 + 一句描述** + **实跑验收 + 重出安装包**。

### 能抄的架构

1. **描述独立成字段，不塞进选段。**
   `excerpt` = 用户亲手选的那段（带引号呈现，是「你的话」）；
   `summary` = 页面自己写的那句描述（左边一条薄荷色竖线，是「页面的话」）。
   两者混在一个字段里会出两个问题：自动抓来的描述会盖掉用户先前选的段落；卡片上分不清哪句是你的、哪句是页面的。

2. **抓取与解析拆开。**
   `packages/yidian-core/page-meta.mjs` 是纯函数（HTML 字符串 → 标题/描述/canonical），不碰网络也不碰 DOM，所以能被单测直接覆盖；
   网络那一段留在各端：桌面端用 Electron 的 `net.fetch`，扩展端直接读 DOM 的 `meta` 标签。
   桌面端自己再加一层 `core/capture.mjs`（链接 → 一条待收下的记录），单测里塞一个假的 `fetchMeta` 就能跑完整条链路，不用真联网。

3. **抓不到也要收下。**
   抓取失败、超时、站点要登录 —— 一律不拦着收下，只是标题退回兜底。
   内容层的价值在于「多带回来一点」，不该因为抓不到就丢掉整条收藏。

4. **合并时真标题优先。**
   兜底标题是我们自己生成的（「域名 · MM-DD HH:mm 收藏」）。
   如果桌面端先存（抓不到，兜底标题）、扩展后存（真标题），合并时不能让兜底标题把真标题挤掉。
   实现上不往记录里塞额外字段，而是用 `isAutoTitle(record)`：把标题和「按这条记录的创建时间算出来的兜底标题」逐字比。

5. **内容不受冷却限制，足迹才受。**
   十分钟冷却原本会连内容一起冻住 —— 用户新选了一段，冷却期内收下就被丢掉。
   现在拆开：标题 / 描述 / 选段随时补上，冷却只管「足迹记不记」。

### 编码这件小事

中文站点还有不少是 GBK 的，直接按 UTF-8 解会得到一堆乱码，标题和描述就白抓了。
`decodePageBytes()` 会先看响应头的 `charset`，再看页面里的 `<meta charset>`，按声明的编码解；编码不认识就退回 UTF-8，不抛错。

### 一条不该抄的

**不要为了「内容更全」去抓正文。**
正文快照涉及版权、存储膨胀和隐私，而且会让「一点」从「帮你想起」变成「帮你囤东西」——
和回看时只带一份到期内容、不显示积压数量的设计口径相冲突。
正文快照是演进路径，不是这一轮的事。

## 3. 改之后的样子

- 桌面端收下一个链接 → 抓回真实标题 + 一句描述；抓不到就退回兜底标题，收藏照收。
- 扩展在真实网页上「替我收好」→ 有选中文字就带选段，没选中就带页面的一句描述。
- 回看卡片：有选段显示选段（带引号），没有就显示描述（左侧竖线）。
- 收藏库列表：同样两栏，描述也能被搜到。

## 4. 还没做的部分（留给下一轮）

> **更新（第二轮）**：下表里的「一句话备注」已经做掉了 —— 见 `research/resurfacing-review-design.md`。
> 那一轮把「回看那一刻该交付什么」按成熟案例重新对了一遍，落成了「你自己写的那句（批注）」与
> 「到期通知正文带内容」。剩下的还在下表里。

| 想做 | 代价 | 我的判断 |
|---|---|---|
| 存档正文 / 首屏截图 | 高（版权、存储、隐私） | 先不做 |
| 记住读到第几屏 | 低（存 scrollY，回看时「从那里继续」） | 值得做，比正文轻 |
| ~~给一条「一句话备注」~~ | — | **已做**：字段叫 `note`，写在收藏库里 |
| 标签 / 分组 / 自定义排序 | 中 | 收藏多了以后找不回来，但现在还早 |
| 坏链检测（到期时链接已经 404） | 中（要发 HEAD 请求） | 值得做，体验影响大 |
| 侧边栏那条采集路径也带描述 | 中（要 executeScript，且不能破坏用户手势栈） | 暂时没做，见下 |

**已知没做的一处：** 扩展的侧边栏（`Alt+Shift+Y`）保存时拿不到描述 ——
侧边栏的页面信息来自 service worker 塞进 session storage 的 `{title, url}`，
要拿到描述得在 SW 里 `chrome.scripting.executeScript`，
但 `chrome.sidePanel.open` 必须留在用户手势调用栈里，前面加 await 会破坏手势 —— 这条路暂时不安全，先不做。

## 5. 验收

- 单测 87/87：新增 `tests/page-meta.test.mjs`、`tests/desktop-capture.test.mjs`，domain 补了描述与合并的用例。
- 扩展 e2e 4/4：新增「宠物在真实网页上：没有选中文字时，用页面的一句话描述顶上」。
- 桌面端 e2e 2/2：新增 `tests/e2e/desktop-capture.test.mjs`（真 Electron × 真本地网页，验 `net.fetch` → `store.json` 里标题和描述都在）。
- 桌面端 × 扩展联调 1/1：配对后收藏照旧立刻对齐。
- `verify:pack` 逐个断言 asar 内容（含新文件 `core/capture.mjs`、`vendor/yidian-core/page-meta.mjs`）。

### 顺带修掉的两个问题

1. **桌面端卡片上的「收下剪贴板」按钮是坏的。**
   `desktop-clipboard-mark` 这个消息只被发出，没人处理 —— `routeMessage` 直接把它丢给 `layer.handleMessage`，
   而消息层里没有这个类型。现在它走和托盘一样的采集通道（带抓标题与描述）。

2. **字体子集被注释绑架。**
   字体守卫扫全文取字（含注释），于是改一句中文注释就要求重建字体子集。
   现在守卫与重建脚本都按「整行注释豁免」处理（行尾注释仍计入，宁可严不可漏），
   字体二进制没动 —— 注释本来就不该参与字体要求。

3. **「免打扰时段内不提醒」这条测试一直是错的。**
   它拿 `start === end` 当静默窗口，而零长度窗口在 `inQuietHours` 里等于「永不静默」，
   所以通知照发、断言必然红。已改成「当前这一小时」这个真实窗口。
