# 一点 · 复现（resurfacing）怎么做：成熟案例对照与这一刀

> 上一步补的是「采集端带回来什么」（标题 + 一句描述）。这一步问的是更靠后的问题：
> **一点把你叫回来的那一刻，到底该给你什么？**
>
> 对标对象：Readwise（每日回顾）、Raindrop（书签管理器）、Instapaper / Pocket（稍后读）。
> 结论先说：**成熟产品在「复现」这一刻交付的是你自己写下的东西，不是一个链接。**
> 一点已经有了「你选的那段」，缺的是「你自己写的那句」—— 以及**到期提醒那一刻就把内容递到眼前**。

---

## 1. 能抄的架构

### 1.1 回顾的最小单元是「你的话」，不是文章

Readwise 的每日回顾推的是**你自己划过的原文**（highlights），一天 5–10 条；
标题与链接只是它的索引。Raindrop 的 Highlights 面板、Instapaper 的 highlights 是同一件事。

> **要点**：复现产品不是「提醒你有个东西该看了」，是「把你自己的话再念给你听一遍」。

一点现在已经有 `excerpt`（你当时选中的那段）✓，方向是对的。缺的是**你自己写下的**。

### 1.2 回顾时要能「回应」，不能只是「读过」

Readwise 的使用指南里有一条被反复强调：**"Don't Just Read, Respond"**，
并且明确建议**用 Notes 字段做主动回忆**（"Use the Notes field for Active Recall"）。
理由也很直白：划了高亮却从不回看，高亮就「死在黑处」。

现在一点的回看卡片只有一个动作：「完成这次回看」。你能**完成**，不能**回应**。
Readwise 的反面教材正好就是这种状态 —— 收下就走，回看时毫无输入。

> **要点**：回看那一刻要留一个「写一句」的出口。

### 1.3 提醒本身就是内容载体

Readwise 的每日邮件**正文就是高亮原文**；Raindrop 的提醒带预览。
一点现在的到期通知正文是固定的一句「一点想再见它一面。」—— 等于在最有价值的三十秒里，
只递给你一个标题。

> **要点**：通知正文该放内容本身（你的话 > 你选的段落 > 页面那句描述），而不是一句气氛话。

### 1.4 回顾要限量、要固定

Readwise 的指南给的两条硬规则：**固定时间 + 每次限量**。
一点的口径更狠（一次只带一份到期内容、不显示积压数量、不惩罚中断）—— 这条不用改，是产品性格。

### 1.5 存档是「资料库定位」才需要的

Raindrop Pro 会给每个网页存一份永久副本（"Even if a page you've saved is taken down, you'll still have a copy"），
并提供全文检索；Instapaper / Pocket 也提供离线阅读。

> **要点**：这是**收藏管理器 / 阅读器**的能力，不是**回看提醒器**的能力。
> 一点是「提醒你想起」，不是「替你囤着」。这一条明确不抄（理由见 §3）。

---

## 2. 产品洞察

1. **「你的话」比「机器的话」更能唤起记忆。**
   Instapaper / Pocket 的笔记、Readwise 的 notes 都是你自己的句子。
   反过来，AI 摘要（Pocket 的 AI summaries、Reader 的 Ghostreader）帮的是**快速消费**，
   不是**记住**。一点坚持本地优先、不调模型，是对的 —— 真能唤起记忆的是你写的那句。

2. **「写一句」这件事本身是复现的一部分，不是额外的活儿。**
   Readwise 把 notes 当成回顾动作的一环。一点如果只在「收下」时采集、在「回看」时只读，
   那条收藏就永远停在「我收藏过」，没有变成「我记得」。

3. **写下的东西是链接失效后唯一还在的东西。**
   链接会 404、会改版、会被付费墙挡住；但「这条对我意味着什么」是你自己的话，
   不会消失。这一层让「留存」这件事第一次有了正当理由 ——
   而这恰好是正文快照做不到、也不该做的（§3）。

4. **成熟玩家把「组织」放在付费墙后面。**
   Readwise **Lite 明确不含 tags / notes / export**，Full 才有；Raindrop 的收藏夹、标签、
   多视图、批量处理是 Pro 的地盘。免费产品的内核被刻意压到最小：
   **收下 → 复现 → 搜索**。一点也是免费的、一次一份的，所以组织层现在不该做。

5. **回看那一刻的信息密度要低，但内容质量要高。**
   一点一次只给一份 —— 那这一份就必须「值得看」。标题 + 域名 + 一段话，是刚好够的一档。

## 3. 明确不抄的

| 成熟做法 | 不抄的理由 |
|---|---|
| Raindrop Pro 的**网页永久副本 + 全文检索** | 定位不同：那是资料库。一点是回看提醒器。而且涉及版权、存储膨胀、隐私。更关键的是：存档的是「别人的内容」，唤起记忆靠的是「你自己的话」 |
| 标签 / 收藏夹 / 多视图排序 / 拖拽排序 | 成熟玩家把这层放在付费墙后面；一点的条目量还没到需要组织的程度，而且「一次一份、不积压」的口径与「管理一堆」相冲突 |
| Readwise 每天 5–10 条的**批量回顾** | 一点的口径是一次一份、不显示积压数量、不惩罚中断 —— 这是产品性格，不为了抄而改 |
| AI 摘要 / Ghostreader 式**机器总结** | 要模型调用与成本；而且真正能唤起记忆的是你自己的话，不是机器的总结 |
| Reader 的**沉浸阅读器 / 离线阅读 / 稍后读队列** | 一点不是阅读器。回看那一刻给的是「想起」与「打开原网页」，不是一篇排版好的文章 |
| Instapaper / Pocket 的**阅读进度 / 恢复到上次位置** | 那属于阅读器内核。复现类产品（Readwise）靠的是 highlights 而不是续读位置。等确认真的需要再补 |
| 每日 5–10 条的**邮件摘要** | 一点已经有系统通知这一层，不做邮件 |
| Raindrop 的**坏链检测 / 重复检测** | 坏链检测有参考价值（到期时链接已 404 体验很差），但要发 HEAD 请求、成本中等，单独立一轮 |

## 4. 分档清单

### A 档（这一轮做，零风险）

**A1. 一句话批注（note）** —— 你自己写的那句。

- 新增 `note` 字段（≤500 字），和 `excerpt` / `summary` 分开：**它是你的话，不是页面的**。
- 写在**收藏库页**（两端同一份 `library.js`）：每条记录一个行内输入框，随时写、随时改、随时清。
- **回看卡片与宠物卡片上展示它**，且优先级最高：你的话 > 你选的段落 > 页面那句描述。
- 可搜索、可导出（Markdown）、可导入、跨端合并（跟着 `updatedAt` 走）。

**A2. 到期通知正文带上内容** —— 提醒那一刻就把话递到眼前。

- 单条到期时，通知正文 = 批注 > 选段 > 描述（截断到 120 字）；都没有才回到原来那句气氛话。
- 多条到期时保持原来的计数口径（「今天有 N 位老朋友想见你。」），不泄露是哪几条。

### B 档（下一轮候选，等你拍板）

- **坏链检测**：到期前发一次 HEAD，链接挂了就标记「可能已经不在了」并给替代提示。
- **续读位置**：记住读到多少，并尝试用文本片段 `#:~:text=` 跳回原处。
- **主动回忆两段式**：卡片先只给线索，你点一下才揭晓原文（Readwise 的 self-testing）。
- **多选段**：一条收藏存多段你划的原文（Readwise 的 highlight 集合）。

### C 档（明确不做，除非定位变了）

- 网页永久副本 / 全文检索 / 离线阅读
- 标签 / 收藏夹 / 多视图
- AI 摘要

---

## 5. 验收

- 单测：`note` 字段、`setNote`、合并时批注不被覆盖、导入导出与搜索都带上批注、`set-note` 消息。
- e2e（真实浏览器）：收藏库里写一句 → 记录里有批注 → 卡片上显示的是你的话。
- e2e（真 Electron）：桌面端收藏库写一句 → `store.json` 里有 → 通知正文带的是这句话。
- `verify:pack` 逐个断言 asar 内容。
