# Research

## 公开平台事实
- RED Skill 通过笔记底部组件被发现，用户点击“去使用”后复制安装口令，再交给自己的 AI 助手。
- Skill 审核通过后仍需挂载到笔记或评论区，单独上传不会自然获得展示。
- 2026 年 7 月已经扩展文件类型，但站内直接运行仍处于逐步开放阶段。
- RED Skill 大赏投稿期为 2026-06-08 至 2026-07-20；当前不应再把新发布包装成参赛投稿。
- 已公开案例里，垂直、结果明确的 Skill 比通用代理更容易被使用；笔记热度和 Skill 使用数并不等价。

## 成熟案例的共同点
- PPT：立即得到一套可见的页面。
- 面试准备：立即得到模拟问题和差距判断。
- 旅行路书、训练计划：立即得到可执行安排。
- 共同结构是“一个具体输入 → 一个立刻看得见的结果”，而不是先解释技术。

## 品牌土壤取证
- 《Brief指导（小红书KOL）》：封面、标题、正文需要围绕同一个用户痛点；产品使用图和清晰行动引导不可缺。
- 《小红书整体框架及玩法》：内容场景词、核心卖点词需要在标题和正文中前置，用户是在具体需求下发现产品。
- 《2023章小蕙小红书直播营销方案》：真实使用、温暖表达和情绪价值比统一话术更能建立信任。

## 对一点的判断
“一点”的长期价值发生在未来，因此第一次使用必须先给即时回报：一张《已收下 · 还有 3 次回看》的记录卡。随后才处理保存、回看和提醒能力。

## 悟鸣课程与公开 Skill 复核
- 课程讲师确认是悟鸣，公开账号为“悟鸣AI”；语音转写中的“雾明”等写法均为误识别。
- 公开仓库：`https://github.com/chujianyun/skills`。仓库把 Skill 分成 Tool Wrapper、Reviewer、Pipeline、Runbook 等任务模式，而不是堆放通用提示词。
- 对“一点”最有用的原则：先定义稳定输出，再反推最少输入；`description` 写清触发与不适用场景；高影响动作先确认；动态状态留在外部可读记录中；把真实失败案例变成 Gotchas。
- “一点”当前只需要一个窄 Skill：收下一条、回看一条。暂不复制悟鸣仓库的复杂目录、安装器或脚本，等跨 Agent 实测暴露问题后再增加。
