# 我把一次重复收藏，改成了“途中偶遇”

> 一点 1.0.2 持续优化记录｜可运行 Demo、真实问题与验证结果

有一次，我在收藏库里看见了两条“合作伙伴中心”。

它们不是两份不同的内容。我只是第一次收藏后，已经见过一两次；到了第三、四天，又在网页里遇见它，却忘了自己是否收藏过，于是顺手又点了一次。

旧版本很诚实地执行了这个动作：再建一条记录，从 1/4 重新开始。原来的那条也还在。

这不是一个严重的错误，反而让我看见了更有意思的用户动作：

**当人再次主动收藏同一份内容，未必是在重复操作，也可能是在途中又认出了它。**

## 收藏之后，人不会一直记得“我收藏过”

收藏工具通常擅长回答“存在哪里”，却很少处理另一个更日常的问题：

- 我已经存过了吗？
- 上一次走到哪一步了？
- 这次又遇见它，算不算一种新的关系？
- 如果仍然重要，我要继续原来的计划，还是重新开始？

对“一点”来说，答案不应该是让用户先回收藏库查重，也不应该弹出一句冷冰冰的“已存在”。

所以 1.0.2 把重复收藏改成了一个更符合真实感受的反馈：

**途中偶遇。原来的计划一直在继续。**

## 同一份内容，只保留一段旅程

现在，再次收下同一网页时：

1. 不会新增一条重复记录；
2. 不会把 2/4、3/4 的进度重置为 1/4；
3. 短时间内重复点击只会确认“刚刚已经记下”；隔一段时间再次遇见，才留下“途中偶遇”的时间；
4. 如果旧版本里已经有重复项，会自动合并，并保留走得更远的进度。

如果你同时装着 Edge 商店版和官网下载的手动版，两份扩展会各自拥有一份本地收藏。可在旧版“我的收藏”中导出备份，再到新版导入；同一网页会自动合并，进度和足迹都会保留。正式从 Edge 商店更新时不需要这一步。

网址后面的追踪参数、页面锚点和常见的末尾斜杠，也不再轻易把同一页误判成不同内容。页面提供 canonical 地址时，一点会优先用它识别正文身份。

这让“一条收藏”从一行静态数据，变成了一段可以继续的关系。

## 收藏库里，多了一条“相见足迹”

1.0.2 的收藏库会显示：

- 第一次收下；
- 第 2、7、30 天的回看；
- 中途再次主动收藏时发生的偶遇；
- 完成一轮后主动重新开始的时间。

这些记录不要求用户整理，也不要求先建文件夹。它只是诚实地留下：你在哪一天又想起了它，哪一次真的回来读了它。

完成 4/4 后，如果这份内容仍然值得继续，也可以重新开始一轮。重新开始是明确的选择，不会因为一次误点悄悄发生。

## 为什么这次没有顺手加入文件夹和 AI 分类

重复收藏很容易把讨论带向“是不是该做文件夹、标签或自动分类”。

但这次我没有加。

当前真正发生的问题，不是收藏太多而找不到，而是**同一份内容被当成两段互不相干的记录**。先把内容身份、回看进度和偶遇关系处理正确，比增加一层整理系统更重要。

等收藏规模真的让人难以定位，或者用户开始反复表达“我想按项目、主题找回来”，再决定文件夹、筛选还是自动分类。现在先不替未来制造维护成本。

## 我怎样确认它真的没有重置

这次不只验证页面能打开。

我在隔离的真实 Edge 环境里加载 1.0.2，完整走了一遍：

- 首次收藏；
- 同一页再次偶遇；
- canonical 地址升级；
- 原回看进度保留；
- 旧重复项自动合并；
- 完成 4/4 后重新开始；
- 收藏库只保留一条记录，并展示完整足迹。

同时，项目的自动检查覆盖网址归一化、重复合并、并发写入、导入备份、权限边界、创空间页面和文案约束。

数据边界没有变化：无需登录，收藏仍只保存在浏览器本地，不读取未选择的网页正文，也不上传收藏记录。

## 从“存下来”到“再次认出来”

一点最初解决的是：重要内容不只见一次。

1.0.2 又往前走了一小步：人和内容的关系，不总是按计划发生。计划之外的再次遇见，也值得被温柔地接住。
