# 12730 下一代产品规格（工作稿）

状态：第一轮盘点完成，按“扩展本体 + ModelScope 体验站”推进。

## 产品承诺

12730 帮用户把“我应该系统学习”缩小成一次轻松的开始：在当前文档 Mark 一下，立即得到 25%；宠物再按 1、2、7、30 天把原文带回来。

它庆祝开始和回来，不把用户的进度解释成掌握度，不制造逾期债务。

## 产品组成

### 浏览器扩展

正式产品，运行在 Notion、ima、飞书和普通网页：

- 点击工具栏或快捷键唤出网页悬浮宠物；
- 宠物默认巡游，到边缘转身；
- 宠物可真实拖动，松开后从新位置继续活动；
- 点击宠物打开文档卡片；
- 第一次 Mark 立即获得 25%；
- 到期时一次只带回一份文档；
- 所有数据默认保存在浏览器本地。

### ModelScope 创空间

公开体验与发布入口，不冒充跨站扩展能力：

- 解释 12730 的产品逻辑；
- 提供可互动的 Mark、回访和四阶段成长演示；
- 展示隐私边界和支持的平台；
- 提供扩展下载和安装说明；
- 后续承载更新日志、反馈入口与可选 AI 体验。

第一代使用 Static 创空间，不依赖 GPU、后端数据库或常驻 Python 服务。

## 下一代的交互基线

以用户确认舒服的 0.2.2 交互为准：

- 卡片默认位于宠物上方，宠物完整露出；
- 保留宽松的卡片排版、明确进度和主操作；
- 保留“暂停巡游”和“暂时收起宠物”；
- 不采用 0.3.1 的小号宠物、四向复杂卡片定位和多层菜单。

选择性保留 0.3.1 的底层修复：

- 扩展更新后的旧节点恢复；
- 并发写入串行化和阶段推进幂等；
- 注入失败的可见反馈；
- 设置迁移与视口约束中经过真实浏览器验证的部分。

## 成熟案例的借鉴边界

- Shimeji：借鉴直接拖动、持续活动、偶发动画和一键开关；不做多宠物和网页元素破坏。
- Readwise：借鉴“合适时间带回一份”；不建立重型收件箱和知识仓库。
- Finch：借鉴温柔鼓励、宠物身份与可选装扮；不把装扮塞进 Mark 主流程。
- RemNote / FSRS：作为未来自适应回访研究；第一代坚持可解释的 1、2、7、30。
- Codex 宠物：借鉴状态动画与直接操控；浏览器版暂不照搬完整 8×11 精灵图协议。

## 第一代成熟版范围

### 必须完成

1. 真实 Chrome 和 Edge 中可拖动、可巡游、不卡住。
2. 卡片不覆盖宠物，宠物不超出视口。
3. 未 Mark、等待、到期、100% 四种状态完整。
4. 1、2、7、30 调度、URL 去重、并发幂等可靠。
5. 到期圆点一次只带回一份，不显示积压数量。
6. 本地记录可查看、打开、删除、导出和导入。
7. 尊重减少动态效果，键盘操作和焦点状态可用。
8. 不读取网页正文，不发送产品数据到网络。
9. ModelScope Static 体验站可公开访问并提供扩展包。

### 完成核心体验后再加入

- 宠物大小调节；
- 2–3 款轻量配色皮肤；
- 更丰富但低打扰的状态动画；
- 用户主动选中文本后的可选 AI 回忆问题。

### 本代不做

- 登录和跨设备同步；
- 强制 AI 摘要或正文采集；
- 皮肤商城、货币、排行榜和连续打卡；
- FSRS、掌握度评分和惩罚性逾期；
- 多宠物同时运行。
